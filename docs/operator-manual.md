# 作業者マニュアル（Operator Manual）

YOLO Tuning Studio を実際に操作しながら、プロジェクト作成から学習・推論・レポート出力までを進めるための手順書です。
各章のスクリーンショットは、すべて**実際に動作しているアプリ**（`operator_docs_demo` という秘密情報を含まないテスト用プロジェクト）から撮影したものです。架空のUIやモック画像は使用していません。

> **前提（共通）**: バックエンド（`http://localhost:8000`）とフロントエンド（`http://localhost:5173` 等）が両方起動していること。起動方法は [ルートREADMEのQuickStart](../README.md#quickstart) を参照してください。

> **このマニュアルの画面について**: 学習・推論・映像・撮影は重い処理のため、開発環境ではドライラン（`YTS_*_DRY_RUN` 環境変数）で高速にダミー動作させることができます。本書のスクリーンショットは、プロジェクト準備〜画像取り込み・撮影ソース・映像/URL推論は撮影の安全性・速さを優先してドライラン環境で撮影しています。一方、**学習・評価・モデル管理・静止画推論・誤検出分析・実験履歴**は、小規模な合成データセット（少数epoch）で実際にUltralytics YOLO学習・推論を実行し、実成果物（重みファイル・グラフ・メトリクス）が生成された状態を撮影したものです（Operator Walkthrough時に検証）。合成データのため精度指標は0付近ですが、これは正常な結果表示です。

---

## 0. アプリ起動後の入口 / プロジェクト選択

### 目的
アプリにアクセスし、作業するプロジェクトを新規作成または選択する。

### 前提条件
バックエンド・フロントエンドが起動済みで、ブラウザでフロントエンドのURLを開いている。

### 操作手順
1. トップ画面（プロジェクト一覧画面）が表示される。
2. 「新規プロジェクト作成」フォームに、プロジェクト名（英数・`_`・`-`のみ）、説明（任意）、タスク種別（物体検出 / セグメンテーション）を入力し「作成」を押す。
3. **作成しても自動ではプロジェクト画面に遷移しません。** 下の「プロジェクト一覧」に追加された行の「開く」を押してプロジェクトに入ります。

### スクリーンショット

![入口: プロジェクト一覧](images/operator/01-projects-list.png)

![プロジェクト作成後の一覧](images/operator/01b-projects-list-after-create.png)

### 正常完了の確認
一覧に作成したプロジェクトの行が表示され、「開く」を押すとプロジェクト準備画面（後述）に遷移する。

### 注意事項 / 失敗時の対処
- 同名プロジェクトを再度作成しようとするとエラーになります（[よくあるエラー](#12-よくあるエラーと安全な対処)参照）。
- タスク種別（物体検出 / セグメンテーション）は作成後の変更を想定していません。

## 1. プロジェクト準備（概要・クラス設計・画像取り込み・撮影ソース）

### 目的
プロジェクトのクラス定義を行い、学習対象の画像を登録する。

### 前提条件
プロジェクトを作成・選択済み。

### 操作手順
1. サイドバー「1 プロジェクト準備」を開く。概要（画像数・ラベル数・クラス数等）とクラス設計が同じ画面にまとまっている。
2. 「クラス設計」で、クラス名を入力して「追加」を押す（複数追加可能）。追加後に「保存」を押すと `classes.yaml` に保存される。
   - IDは並び順で0始まりの自動採番。**既存クラスの並びは、学習・データセット作成後は変更しないでください**（ラベルの整合性が崩れます）。
3. 「画像取り込み」は3つのタブで切り替え:
   - **フォルダ取り込み**（推奨）: フォルダを選ぶと対象拡張子の画像を一括取り込み。重複・破損は自動スキップ。
   - **個別アップロード**: 少数の画像を直接選んで追加。
   - **カメラ・URLで撮影**: 接続中のカメラ、またはネットワークカメラの映像URLを撮影ソースとして登録し、個別撮影または自動撮影で画像を取得。

### スクリーンショット

![クラス設計: 追加・保存後](images/operator/03-setup-classes-saved.png)

![画像取り込み: 個別アップロード結果+登録画像一覧](images/operator/04-setup-images-uploaded.png)

![フォルダ取り込みタブ（パス未入力の初期状態）](images/operator/06-setup-folder-import-tab.png)

#### 撮影ソース（カメラ・URL）

![撮影ソース（カメラ/URL）タブ: 初期状態（未登録）](images/operator/05-setup-capture-tab.png)

「+ ソースを追加」で、ローカルカメラまたはネットワークカメラのURLを登録できます。

![撮影ソース新規登録フォーム](images/operator/05b-setup-capture-add-form.png)

- 種別を「URL（RTSP/HTTP・MJPEG）」にすると、映像URLと名前（ラベル）の入力欄が表示されます。
- ネットワークカメラのビューワページのURL（`view.shtml?...&imagepath=...` 形式）を貼り付けた場合、クエリの実映像パスを自動検出してストリームURLへ解決します。
- 登録後、「▶ 全て開始」で一括自動撮影、または各ソースの「今すぐ撮影」で個別撮影ができます。自動撮影間隔は全ソース共通（壁時計基準で同期）です。

### 正常完了の確認
「登録画像」に取り込んだ画像がサムネイル表示され、枚数が概要欄の「画像」数に反映される。

### 注意事項 / 失敗時の対処
- 撮影ソースのURL欄に認証情報を含める場合は `http://ユーザー名:パスワード@ホスト/...` の形式で入力します。ログ・エラーメッセージ上ではパスワード部分は `***` にマスクされますが、**画面上の「保存済みURLから選択」欄や設定値そのものには平文で表示されます**（同一運用者内での利用が前提のため）。
- ネットワークカメラのURLは `http(s)://` または `rtsp(s)://` で始まる必要があります。`file://` 等は拒否されます。

## 2. 画像選別

### 目的
低品質（暗い・明るい・ブレ・小さい）画像や重複画像を検出し、学習対象から除外する。

### 前提条件
画像を1枚以上取り込み済み。

### 操作手順
1. サイドバー「2 画像選別」を開く。
2. 「チェック設定」で `min_width` / `min_height` / `blur_threshold` / `dark_threshold` / `bright_threshold` と重複検出の有無を設定し、「チェック実行」を押す。
3. 実行結果は `included`（採用）/ `review`（要確認）/ `excluded`（除外）等のタブで絞り込める。画像ごとに「採用」「削除」ボタンや回転ボタンがある。

### スクリーンショット

![画像選別: 実行前](images/operator/07-selection-before-run.png)

![画像選別: 実行後（included/excluded/review）](images/operator/08-selection-after-run.png)

### 正常完了の確認
各カテゴリ（総数・included・excluded・review・duplicate・small・dark・bright・blur）の件数が表示される。

### 注意事項 / 失敗時の対処
- **「削除」は raw/processed の画像本体・サムネイル・アノテーションラベルを含めて完全に消去し、元に戻せません。** 除外（excluded）にするだけなら削除ボタンは押さないでください。
- 削除中に一部ファイルが使用中などで失敗した場合は、成功分は反映されつつ409エラーで通知されます（部分的な消し漏れにはなりません）。

## 3. 前処理

### 目的
リサイズ・明るさ/コントラスト・グレースケール・シャープ・CLAHE等の画像加工を、`raw` → `processed` へ非破壊で適用する。

### 前提条件
画像を取り込み済み。

### 操作手順
1. サイドバー「3 前処理」を開く。
2. `job_name` を確認し、必要な処理オプションを有効化して値を設定する。
3. 「前処理を実行」を押す。

### スクリーンショット

![前処理設定画面（実行前）](images/operator/09-preprocess-settings.png)

![前処理: 実行後（processed情報）](images/operator/10-preprocess-after-run.png)

### 正常完了の確認
処理後、`processed/images` の枚数・出力形式などの情報が表示される。Before/Afterプレビューでも確認できる。

### 注意事項 / 失敗時の対処
- `raw` 画像は変更されません（前処理は常に `processed` へ別出力）。
- 既存のアノテーション済みラベルがある状態で前処理を再実行すると警告が出ます（座標系がズレる可能性があるため）。

## 4. アノテーション

### 目的
BBOX（物体検出）またはポリゴン（セグメンテーション）でラベルを作成・編集する。

### 前提条件
クラスを1つ以上定義済み、画像を取り込み済み。

### 操作手順
1. サイドバー「4 アノテーション」を開く。
2. 上部のクラスチップから対象クラスを選択する（初期状態は先頭のクラスが選択されている）。
3. 画像上でドラッグしてBBOXを描画する（セグメンテーションタスクの場合はポリゴンを描画）。
4. 「保存（Ctrl+S）」で保存する。画像一覧の「済/未」で進捗を確認できる。
5. **左の画像一覧をクリック、または「→（次の画像）」ボタンで次の画像に切り替え、手順2〜4を繰り返す。** 次のデータセット作成工程では、ラベル付けした画像（または明示的に「未ラベル画像を含める」を選んだ画像）が対象になるため、学習に使いたい画像は一通りラベル付けしておく。

### スクリーンショット

![アノテーション画面: 初期状態（画像+クラス一覧）](images/operator/11-annotate-initial.png)

![アノテーション: BBOX作成後](images/operator/12-annotate-with-box.png)

### 正常完了の確認
右側の「ボックス」一覧に作成したラベルが表示され、保存すると「未保存」表示が消える。

### 注意事項 / 失敗時の対処
- 画像切り替え前に保存を忘れると変更が失われます（「未保存」表示を確認する）。
- SAM補助（導入時）を使うと、クリック等から自動でポリゴン候補を生成できます。

## 5. データセット作成 / validation

### 目的
`raw`/`processed` 画像とラベルから、train/val/test に分割した学習用データセット（`data.yaml`込み）を生成する。

### 前提条件
アノテーション済みの画像がある（未ラベル画像のみを含める設定も可能）。

### 操作手順
1. サイドバー「5 データセット作成」を開く。
2. 右側の「ラベル品質チェック」で「チェック実行」を押し、`error` がないことを確認する（`error` があると作成は中止されます）。
3. 左側の作成フォームで `dataset_name`・分割比率（train/val/test、合計1.0）・対象画像の条件（画像選別の反映有無、review/空ラベル/未ラベルを含めるか）を設定し「作成」を押す。

### スクリーンショット

![データセット作成フォーム（ラベル品質チェック含む）](images/operator/13-dataset-form.png)

![データセット作成後（一覧に追加）](images/operator/14-dataset-created.png)

### 正常完了の確認
「作成済みデータセット」一覧に追加され、`data.yaml` のパスが表示される。

### 注意事項 / 失敗時の対処
- 「画像選別を反映（excludedを除外）」がデフォルトで有効です。選別未実行や、選別結果によっては対象画像が0枚になり作成に失敗することがあります（`review`画像・未ラベル画像を含めるかどうかの設定を見直してください）。
- 分割比率の合計が1.0でないと作成ボタンが無効になります。

## 6. 学習

### 目的
Ultralytics YOLO によるモデル学習を開始する。

### 前提条件
データセットを作成済み。

### 操作手順
1. サイドバー「6 学習」を開く。
2. 左側でデータセット・`job_name`・ベースモデル・ハイパーパラメータ（epochs/imgsz/batch/device/workers/patience/seed）を設定する。
3. 右側「データ拡張（オーギュメンテーション）」でプリセットを選択・調整する（学習時にランダムに適用される）。
4. 「学習開始」を押す。学習は別プロセスで動作するため、実行中も画面操作・API応答は継続する。

### スクリーンショット

![学習ジョブ開始フォーム+データ拡張プリセット](images/operator/15-train-form.png)

![学習ジョブ開始直後（一覧・状態）](images/operator/16-train-job-started.png)

![学習ジョブ完了後の状態表示](images/operator/17-train-job-completed.png)

### 正常完了の確認
下部の「ジョブ一覧」で `status` が `queued` → `running` → `completed` と変わることを確認する。「詳細」からログを確認できる。

上記は実際にUltralytics YOLO学習（epochs=3の小規模テスト）を実行し、`completed` になった状態です。実際の重みファイル（best.pt/last.pt）が生成されています。学習データ量・epochs・デバイスによっては数分〜数時間かかる場合があります。

### 注意事項 / 失敗時の対処
- 同名の `job_name` で「上書き」しない限り、既存ジョブと重複すると409エラーになります。
- **実行中（queued/running）のジョブは、上書き設定に関わらず削除・上書きされません**（誤って上書きしてもエラーになるだけで、実行中ジョブのファイルは保護されます）。

## 10. 映像 / URL推論（実装済み範囲）

### 目的
接続中のカメラ、またはネットワークカメラの映像URL（RTSP/HTTP・MJPEG）にリアルタイム推論する。

### 前提条件
学習済みモデルが存在する。ネットワークカメラを使う場合は同一LAN等から到達可能なURL。

### 操作手順
1. 推論テスト画面の上部タブ「映像（カメラ/URL）」を選ぶ。
2. 映像ソースを「ローカルカメラ」または「URL（RTSP/HTTP・MJPEG）」から選ぶ。
3. カメラの場合はカメラ一覧から選択、URLの場合はURL欄に入力する（ビューワページのURLを貼ると実ストリームURLへ自動解決）。
4. `video_job_name`・学習ジョブ・weight・映像FPS/推論FPS/conf/iou/imgsz/device・前処理を設定し「映像推論を開始」を押す。

### スクリーンショット

![推論テスト: 映像モード（カメラ）フォーム](images/operator/22-infer-video-camera-form.png)

![推論テスト: 映像モード（URL）フォーム](images/operator/23-infer-video-url-form.png)

### 正常完了の確認
開始後、右側「ライブ映像」に注釈付き映像が表示される。実行中は「実行中」バッジが表示され、設定（FPS等）は再接続なしで即時変更できる。URL取得に成功すると、そのURLがプロジェクトに記憶され次回以降ドロップダウンから選べる。

### 注意事項 / 失敗時の対処
- 実行中のジョブは、上書き設定に関わらず上書き・削除されません（学習ジョブと同様の保護）。
- URLが `http(s)://`/`rtsp(s)://` で始まらない、またはホスト部分を認識できない場合は400エラーになります。
- 到達不能なURLを指定すると、接続試行を数回リトライした後 `failed` になります（環境によっては最初の接続試行だけで数十秒以上かかることがあります）。
- 認証が必要なURLで401/403が返る場合、`http://ユーザー名:パスワード@ホスト/...` の形式で認証情報を埋め込む必要がある旨のヒントが表示されます。ログ・エラーメッセージ上のパスワードは `***` にマスクされます。

## 11. 結果確認（誤検出分析 / 実験履歴 / レポート）

### 誤検出分析

推論結果とGTラベルをIoU比較し、TP/FP/FN/class_mismatchやクラス別統計を確認します。

1. サイドバー「9 誤検出分析」を開く。
2. 右上の「推論ジョブ」で対象の推論ジョブを選ぶ（**推論ジョブがない場合は空状態のまま**。先に[静止画推論](#9-静止画推論)を実行しておく）。
3. `iou_threshold` / `conf_threshold` を必要に応じて調整し、「分析実行」を押す。

![誤検出分析画面](images/operator/24-analysis.png)

## 12. よくあるエラーと安全な対処

| 状況 | エラー例 | 対処 |
|---|---|---|
| 同名プロジェクトを再作成 | ![既存プロジェクト名での作成失敗](images/operator/28-error-duplicate-project.png) | 別名にするか、既存プロジェクトを開く。 |
| 同名の学習ジョブを重複作成 | ![同名学習ジョブの重複（409）](images/operator/29-error-duplicate-job.png) | 「上書き」を有効にするか、別の `job_name` にする。ただし実行中ジョブは上書き不可。 |
| 推論対象画像を未選択のまま実行 | 「推論対象の画像を1枚以上選択してください。」 | 画像サムネイルをクリックして1枚以上選択してから実行する。 |
| 重みファイルが存在しない | 「Error: モデル 'best.pt' が見つかりません: ...」（[静止画推論の実行結果例](images/operator/21-infer-image-result.png)参照） | 対象の学習ジョブが実際に完了し重みが生成されているか、モデル管理画面で確認する。 |
| データセット作成時、対象画像が0枚 | 「Error: 対象画像が0枚です。」 | 画像選別の反映設定・review/未ラベル画像を含める設定を見直す。 |
| 映像/URLソースが不正 | 「source_url は http(s):// または rtsp(s):// で始めてください。」等 | URL形式を確認する。認証情報がある場合は `http://user:pass@host/...` 形式にする。 |

**共通の安全指針**:
- 削除操作（画像選別の削除等）は元に戻せません。実行前に対象を確認してください。
- 実行中（queued/running）のジョブは、同名での上書きが常に拒否されます。誤って上書きしようとしてもエラーになるだけで、実行中ジョブのファイルは変更・削除されません。
